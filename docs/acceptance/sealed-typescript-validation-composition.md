## Exact change

Only `verifySealedTypeScriptBaseExchangeAssets` composes its three recursive native
full validations into one owned synchronous observation. At its entry the unchanged
native verifier hashes every privately recorded runtime, compiler, linker, SDK
header, native source, copied runtime and compiled binary, preserving the original
pins, descriptor reads, file/parent metadata and fixture/SDK/root checks.

Both exchange source/binary full-read rounds, all three pair/root boundaries and
the final new-row named/ancestry barrier remain. After each round the exact private
native row set and its root/SDK/fixture identities are checked again. The composition
also finishes with a native barrier. Each such barrier puts a complete native named
row check after the last fixture check, before the final exchange named rows.

This removes two native full rereads per exchange verification, not an entire
launcher boundary. The dependency bundle still invokes exchange verification seven
times through the source/copies graph: 21 native full traversals become seven. Across
eight bundles the static count becomes 56 instead of 168. These are call-graph
counts, not measured latency or resource savings. Every independent exchange
verification starts with a fresh complete native hash; there is no cross-call cache,
expiry interval or continuing certificate.

`observeSealedTypeScriptNativeAssetsBuild` is confined to engineering acceptance
helpers. It takes the original private native mint and the fixed synchronous
exchange inspection. It yields no record, success object or authority. A barrier
closure selects no paths and becomes unusable when the call exits. Async/generator
callbacks, extra arguments, non-undefined results (including promises/thenables)
and same-build reentry fail closed. Reentry poisons the enclosing operation even
if its exception is caught. Finally cleanup always closes the active scope.
Observed native validation failures permanently invalidate the native mint.
Exchange-owned inspection failure invalidates the exchange mint; it does not invent
a change to an otherwise independently current native build.

## Assumptions and limits

The original engineering path explicitly requires a trusted, quiescent parent
filesystem. Under that condition, the complete initial byte validation plus current
inode/device/type/owner/mode/link/size/mtime/ctime and named parent lineage barriers
establish the needed same-call observation. Relevant changes or replacements in the
supported metadata model invalidate it. Roots and retained private derivation
relationships are not selected from public reports.

This is not protection against a hostile filesystem, mapped changes that leave all
observed metadata unchanged, arbitrary mutation caused by metadata calls, or future
changes after return. The targeted test deliberately changes bytes after hashing
without changing synthetic metadata: the data-only observation cannot detect that
unsupported case, while the next full independent hash rejects it. That limitation
is explicit; this mechanism must not be used as the sealed-input guarantee or a
compiler verification receipt. The actual native sealing prerequisite remains open.
