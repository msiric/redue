# First-loop acceptance (coordination only)

This validates the new development workflow, NOT REDUE's portable-evidence claim.
No results are prefilled. The installer must record what actually happened.

## Prerequisites

- [ ] Existing work and active tasks are preserved; one director owns coordination.
- [ ] Current native role configuration loads; model/tool/sandbox/account route recorded.
- [ ] No separately billed API fallback, secret migration, global policy weakening,
      public release or extra infrastructure introduced.
- [ ] The real product plan and resume records are accessible to the director.

## One actual loop

- [ ] Director independently identifies one small useful existing REDUE task.
- [ ] Director sends a bounded assignment to a native implementer thread.
- [ ] Worker works in its designated checkout without a competing production writer.
- [ ] Director waits through native completion tools; owner sends no 'continue'.
- [ ] Worker returns exact revision and actual test evidence, not only a narrative.
- [ ] A fresh reviewer examines the fixed candidate, source and acceptance limits.
- [ ] Director reads relevant source/evidence and makes its own decision.
- [ ] A real review finding, if present, returns to the implementer automatically;
      do not invent a defect to force this branch. If absent, mark this branch NOT EXERCISED.
- [ ] Director updates the existing tracker/resume and selects/starts the next unblocked
      task without an owner relay.

## Controls

- [ ] Researcher answers one genuine unresolved current-source question when needed,
      with primary citations; otherwise mark NOT NEEDED rather than fake research.
- [ ] A real unavailable resource is recorded per lane; independent work continues.
      Do not perform a risky action to manufacture a denial test.
- [ ] Owner pause is honored. After a deliberate owner resume, the director reconciles
      current work before continuing. Report if not exercised during initial setup.
- [ ] Private resume location/active thread identity is recorded for manual client
      restart. Automatic recovery is NOT PROVIDED by this starter setup.

## Final record

Use the existing tracker with a short subsection:

    runtime/model:
    native roles actually loaded:
    effective sandbox/approval route:
    task/worker/review revision:
    actual tests and review outcome:
    next task selected without owner relay:
    controls unrun:
    owner action remaining:

A successful role-file parse alone is NOT a live loop PASS. Do not certify a
reviewer's sandbox based only on a TOML declaration when runtime overrides differ.

## Herdr-specific acceptance

- [ ] Installed client/server version and owned calling pane identified.
- [ ] Existing writers checkpointed; one director owns the continuing goal.
- [ ] Native worker/reviewer threads used rather than duplicate terminal workers.
- [ ] No other Herdr workspace read or changed; no server restart or upgrade.
- [ ] Private pane/native-thread resume identifiers recorded.
- [ ] Detach/reattach documented for the installed release; actual test PASS or NOT RUN.
- [ ] Sleep/reboot recovery not claimed from terminal persistence alone.
